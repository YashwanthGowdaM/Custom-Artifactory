# Custom Artifactory — VM Edition

A lightweight, self-hosted **artifact repository** you install directly on an Ubuntu virtual machine or bare-metal server with a single script. It combines **nginx WebDAV** (for fast, scriptable upload/download of very large files) with a modern **PHP + Bootstrap web UI** for browsing, searching, uploading, renaming and deleting artifacts, all protected by HTTP Basic Authentication.

Use it to host build outputs, release binaries, installers, ISOs, model weights, database dumps, or any other large files that you want to fetch with `curl` / `wget` from CI pipelines, servers, or your laptop.

> **Looking for the container version?** This edition installs everything natively on the host with `install.sh`. There is no Docker involved.

## Features

**Storage & transfer**
- Upload and download files up to **20 GB** each (configurable).
- Long timeouts (1 hour) for slow links and large transfers.
- Nested folders with automatic creation of intermediate paths on `PUT`.
- Standard **WebDAV** verbs: `PUT`, `DELETE`, `MKCOL`, `COPY`, `MOVE`, `PROPFIND`, `OPTIONS`.

**Web UI**
- Folder tree sidebar plus breadcrumb navigation.
- Live **search / filter**, sortable columns (name, size, modified date) and incremental "load more" for large folders.
- **Drag-and-drop upload** (including whole folders), with a per-file queue, progress, speed/ETA, cancel and retry.
- Create folders, **rename/move** and **delete** items from the UI.
- Repository statistics (item counts and total size).
- One-click **copy URL** and ready-made **`curl` / `wget`** download and upload commands.
- **Light / dark theme** toggle, responsive layout with a collapsible sidebar.
- Keyboard shortcuts for power users.

**Operations**
- No database and no containers; just nginx and PHP-FPM managed by `systemd`.
- Interactive, guided installer that prompts for credentials (with password confirmation).
- Services enabled at boot, with the nginx config validated (`nginx -t`) before reload.

## Architecture

```
                        ┌──────────────────────── Ubuntu 24.04 VM ────────────────────────┐
                        │                                                                  │
  Browser ──HTTP:80──►  │  nginx ──► /browser/  ──► PHP-FPM 8.3 ──► index.php (UI, mkdir, │
                        │    │                                       upload handler)       │
                        │    │                                                             │
  curl / wget / CI ───► │    └───► /artifacts/ ──► nginx WebDAV (PUT/GET/DELETE/MKCOL/     │
                        │                           COPY/MOVE/PROPFIND/OPTIONS)            │
                        │                                   │                              │
                        │                                   ▼                              │
                        │                      /var/www/html/artifacts  (storage)          │
                        └──────────────────────────────────────────────────────────────────┘
```

| Path | Served by | Purpose |
|------|-----------|---------|
| `/browser/` | PHP-FPM | The web UI and its upload / create-folder handler (requires Basic Auth) |
| `/artifacts/` | nginx WebDAV | Raw file storage and transfer endpoint (requires Basic Auth) |

Both locations share one credentials file, `/etc/nginx/.htpasswd`, created by the installer.

## Project Structure

```
Custom-Artifactory-OnVms/
├── install.sh              # One-shot installer (run as root)
├── nginx/
│   ├── artifacts           # nginx site config (UI, WebDAV, PHP, upload limits)
│   └── .htpasswd           # Empty placeholder; real file is generated by install.sh
└── html/
    └── browser/
        ├── index.php       # UI markup + backend (listing, upload, mkdir, path sanitising)
        ├── script.js       # Frontend logic (search, sort, uploads, rename, delete, theme)
        └── style.css       # Design tokens, layout, light/dark themes
```

### What each file does

| File | Description |
|------|-------------|
| **`install.sh`** | Interactive installer. Prompts for a username and password, installs packages, writes the PHP upload limits, installs the nginx site, copies the UI to `/var/www/html`, generates the password file, injects credentials into `script.js`, sets permissions, enables services and reloads nginx. |
| **`nginx/artifacts`** | Defines the `/browser/` UI location, the `/artifacts/` WebDAV location, PHP handling, a 20 GB body limit and 3600 s timeouts. Dotfiles are denied. |
| **`html/browser/index.php`** | Renders the UI and handles `POST` actions (`upload`, `mkdir`). Includes path-traversal protection (`safeRel`), filename validation and directory listing. |
| **`html/browser/script.js`** | Client-side behavior: `XMLHttpRequest` uploads with progress, and `fetch` with `DELETE` / `MOVE` for WebDAV actions. |
| **`html/browser/style.css`** | Design tokens and styling for light and dark themes. |

## Prerequisites

- A VM or server running **Ubuntu 24.04** (the installer hard-codes PHP 8.3 paths, so other releases need script changes).
- **Root access** (the script exits if not run as root).
- Outbound internet access during install (for `apt`).
- Inbound port **80** open in the host firewall and any cloud security group.
- Enough disk space under `/var/www/html/artifacts` for your artifacts.
- Clients' browsers need access to `cdn.jsdelivr.net` for Bootstrap styles and icons (see [Troubleshooting](#troubleshooting)).

## Installation

### 1. Copy the project to the VM

```bash
unzip Custom-Artifactory-OnVms.zip
cd Custom-Artifactory-OnVms
```

### 2. (Recommended) Set `server_name`

Open `nginx/artifacts` and replace the hard-coded IP address with your server's IP or domain:

```nginx
server_name artifacts.example.com;   # or your server's IP, or "_" to match anything
```

> Because this is the only nginx site, requests are still served even if the value doesn't match, but setting it correctly is cleaner and is required for HTTPS with Certbot.

### 3. Run the installer as root

```bash
sudo bash install.sh
```

You will be asked for:

1. **Artifact Username**
2. **Artifact Password** (typed twice, input hidden)

### 4. Open the UI

When the script finishes it prints the URLs:

```
Browser : http://<server-ip>/browser/
Upload  : curl -u <user>:'********' -T ./FILE http://<server-ip>/artifacts/Test/
```

Visit the **Browser** URL and sign in with the credentials you entered.

## What the Installer Does

In order, `install.sh`:

1. Verifies it is running as **root**.
2. Prompts for the username and a confirmed password.
3. Runs `apt update` and installs `nginx`, `nginx-extras` (provides the WebDAV `dav_ext` module), `php-fpm`, `php-cli` and `apache2-utils` (`htpasswd`).
4. Writes `/etc/php/8.3/fpm/conf.d/99-artifact-upload.ini` with the 20 GB upload limits.
5. Removes the default nginx site and installs `nginx/artifacts` as `/etc/nginx/sites-available/artifacts`, symlinked into `sites-enabled`.
6. Copies `html/*` to `/var/www/html/` and creates `/var/www/html/artifacts`.
7. Creates `/etc/nginx/.htpasswd` with `htpasswd -bc` (this **replaces** any existing password file).
8. Rewrites the `DL_USER` / `DL_PASS` constants in `/var/www/html/browser/script.js` with your credentials.
9. Sets ownership to `www-data:www-data`, directories to `775` and files to `664`.
10. Enables and restarts `php8.3-fpm`, validates the nginx config with `nginx -t`, and reloads nginx.
11. Prints the access URLs.

## Configuration

### Credentials

Credentials are collected interactively by `install.sh`; there are no environment variables in this edition.

> **Tip:** Avoid the characters `|`, `&`, `\` and `'` in the username/password. The installer writes them into `script.js` with `sed`, and these characters can break the substitution (or the resulting JavaScript).

### Upload limits

Limits live in two places and should be kept in sync:

| Setting | Location | Default |
|---------|----------|---------|
| `client_max_body_size` | `/etc/nginx/sites-available/artifacts` (two places) | `20G` |
| `client_body_timeout` | `/etc/nginx/sites-available/artifacts` | `3600s` |
| `fastcgi_read_timeout` / `fastcgi_send_timeout` | `/etc/nginx/sites-available/artifacts` | `3600` |
| `upload_max_filesize` / `post_max_size` | `/etc/php/8.3/fpm/conf.d/99-artifact-upload.ini` | `20G` |
| `max_execution_time` / `max_input_time` | `/etc/php/8.3/fpm/conf.d/99-artifact-upload.ini` | `3600` |
| `memory_limit` | `/etc/php/8.3/fpm/conf.d/99-artifact-upload.ini` | `512M` |

Uploads from the web UI are sent as multipart `POST` requests to the PHP handler (so the PHP limits apply), while `curl -T` uploads go straight to nginx WebDAV (so only the nginx limits apply).

After editing, apply the changes:

```bash
sudo nginx -t && sudo systemctl reload nginx
sudo systemctl restart php8.3-fpm
```

### Port

The site listens on port **80**. To change it, edit the two `listen` lines in `/etc/nginx/sites-available/artifacts`, reload nginx, and update your firewall rules.

### Storage location

Artifacts are stored in `/var/www/html/artifacts`. To use a different disk or mount, either mount that volume at this path or use a symlink:

```bash
sudo systemctl stop nginx
sudo mv /var/www/html/artifacts /data/artifacts      # or mount a disk here
sudo ln -s /data/artifacts /var/www/html/artifacts
sudo chown -R www-data:www-data /data/artifacts
sudo systemctl start nginx
```

If you change the path itself, update `$baseDir` in `index.php` and the `root` in the nginx config so they stay consistent.

### Web UI

Open `http://<host>/browser/`.

| Action | How |
|--------|-----|
| Browse folders | Click folders in the table or the sidebar tree |
| Search | Type in the search box or press `/` |
| Sort | Click the Name / Size / Modified column headers |
| Upload | Click **Upload**, drag files/folders onto the page, or press `U` |
| New folder | Click **New folder** or press `N` |
| Rename / move | Use the row action buttons |
| Delete | Use the row action buttons (confirmation required) |
| Copy download link | Row actions: copy URL, `curl` or `wget` command |
| Properties | Row action menu → Properties |
| Toggle theme | Theme button or press `D` |
| Refresh | Refresh button or press `R` |

| Key | Action |
|-----|--------|

| `U` | Open upload dialog |

| `D` | Toggle dark mode |

### Command-line / API usage (WebDAV)

Replace `HOST` with your server address and `PASSWORD` with your password.

**Upload a file** (intermediate folders are created automatically):

```bash
curl -u admin:PASSWORD -T ./app-1.2.3.tar.gz \
  http://HOST/artifacts/releases/app/1.2.3/app-1.2.3.tar.gz
```

Uploading to a path ending in `/` (as in the installer's example) places the file inside that folder using its original name:

```bash
curl -u admin:PASSWORD -T ./app-1.2.3.tar.gz http://HOST/artifacts/Test/
```

**Download a file:**

```bash
curl -u admin:PASSWORD -O http://HOST/artifacts/releases/app/1.2.3/app-1.2.3.tar.gz
# or
wget --user=admin --password=PASSWORD http://HOST/artifacts/releases/app/1.2.3/app-1.2.3.tar.gz
```

**Resume a large download:**

```bash
curl -u admin:PASSWORD -C - -O http://HOST/artifacts/isos/big-image.iso
```

**Create a folder:**

```bash
curl -u admin:PASSWORD -X MKCOL http://HOST/artifacts/releases/
```

**List a folder (PROPFIND):**

```bash
curl -u admin:PASSWORD -X PROPFIND -H "Depth: 1" http://HOST/artifacts/releases/
```

**Delete a file:**

```bash
curl -u admin:PASSWORD -X DELETE http://HOST/artifacts/releases/app/1.2.3/app-1.2.3.tar.gz
```

**Move / rename:**

```bash
curl -u admin:PASSWORD -X MOVE \
  -H "Destination: http://HOST/artifacts/releases/app/latest.tar.gz" \
  http://HOST/artifacts/releases/app/1.2.3/app-1.2.3.tar.gz
```

**Copy:**

```bash
curl -u admin:PASSWORD -X COPY \
  -H "Destination: http://HOST/artifacts/backup/app-1.2.3.tar.gz" \
  http://HOST/artifacts/releases/app/1.2.3/app-1.2.3.tar.gz
```

### CI/CD examples

**GitHub Actions**

```yaml
- name: Publish artifact
  run: |
    curl --fail -u "${{ secrets.ARTIFACT_USER }}:${{ secrets.ARTIFACT_PASSWORD }}" \
      -T build/app.zip \
      "http://${{ secrets.ARTIFACT_HOST }}/artifacts/builds/${{ github.run_number }}/app.zip"
```

**GitLab CI**

```yaml
publish:
  stage: deploy
  script:
    - curl --fail -u "$ARTIFACT_USER:$ARTIFACT_PASSWORD" -T dist/app.zip "http://$ARTIFACT_HOST/artifacts/builds/$CI_PIPELINE_ID/app.zip"
```

**Jenkins (shell step)**

```bash
curl --fail -u "$ARTIFACT_USER:$ARTIFACT_PASSWORD" -T target/app.jar \
  "http://$ARTIFACT_HOST/artifacts/builds/$BUILD_NUMBER/app.jar"
```

## Day-2 Operations

### Service management

```bash
sudo systemctl status nginx php8.3-fpm
sudo systemctl restart nginx
sudo systemctl restart php8.3-fpm
sudo nginx -t                              # validate config
```

### Logs

```bash
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log
sudo journalctl -u php8.3-fpm -f
```

### Changing the username or password

Re-run the installer; it regenerates the password file and re-injects credentials into `script.js`. Your stored artifacts are **not** touched, because they live in `/var/www/html/artifacts`, which is not part of the `html/` folder being copied.

```bash
cd Custom-Artifactory-OnVms
sudo bash install.sh
```

Note that `htpasswd -bc` rewrites the file, so only the new user will exist afterward.

### Updating the UI

Replace files in `html/browser/`, then re-run `sudo bash install.sh` (this also resets credentials). Alternatively copy the files manually and re-apply ownership:

```bash
sudo cp -r html/* /var/www/html/
sudo chown -R www-data:www-data /var/www/html
```

Manual copying overwrites `script.js`, so re-run the credential `sed` lines from the installer or simply use `install.sh`.

### Backups

```bash
sudo tar czf artifacts-backup-$(date +%F).tar.gz -C /var/www/html artifacts
# or incrementally to another host
sudo rsync -aH --info=progress2 /var/www/html/artifacts/ backup-host:/backups/artifacts/
```

### Monitoring disk usage

```bash
df -h /var/www/html
du -sh /var/www/html/artifacts
```

Uploads of up to 20 GB each can fill a disk quickly, so consider an alert on free space.

## Security Notes

Please read this section before exposing the service to the internet.

1. **Credentials are visible to anyone who can log in.** The installer writes your username and password into `/var/www/html/browser/script.js` so the UI can generate ready-to-run `curl` / `wget` commands. Any authenticated user can read them from the page source. Since the same credentials grant full read/write/delete access, treat every user of the UI as an administrator, or modify the project to use a separate **read-only** account for this feature.
2. **Remove the hard-coded default credentials from the repository copy of `script.js`.** The shipped `DL_USER` / `DL_PASS` values are overwritten at install time, but they remain in the source you distribute. Replace them with neutral placeholders (for example `'changeme'`) and rotate any password that has already been committed or shared.
3. **HTTP only.** The shipped configuration listens on port 80 without TLS, so Basic Auth credentials and files travel in clear text. Enable HTTPS for anything beyond a trusted network (see below).
4. **Single shared account.** There are no per-user roles or audit logs.
5. **Path traversal protection** is implemented for UI actions (`safeRel` rejects `..` and null bytes), dotfiles are denied by nginx, and uploaded filenames beginning with `.` are rejected.
6. **No file-type restrictions.** Anything can be uploaded. Do not enable PHP execution under `/artifacts/`; the shipped config only routes `.php` requests through PHP-FPM, so keep that in mind if you change location rules.
7. **Runs on a shared host.** Unlike the container edition, nginx and PHP run directly on the VM. Use a dedicated VM or restrict access accordingly.

## Production Hardening

**Firewall**

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp        # if you enable HTTPS
sudo ufw enable
# Or restrict to a trusted network:
# sudo ufw allow from 10.0.0.0/8 to any port 80 proto tcp
```

Also open the port in your cloud provider's security group / network ACL.

**Enable HTTPS with Let's Encrypt**

Set a real domain in `server_name` first, point DNS at the VM, then:

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d artifacts.example.com
```

Certbot adds a TLS server block and an HTTP→HTTPS redirect. Re-check that `client_max_body_size 20G` and the timeouts still apply in the new block.

**Other recommendations**
- Use a long, random password and rotate it regularly.
- Restrict access by IP / VPN where possible.
- Turn on unattended security upgrades (`sudo apt install unattended-upgrades`).
- Schedule regular backups of `/var/www/html/artifacts`.
- Keep `logrotate` enabled for nginx logs.
- Run a read-only account for download-only consumers (requires a second `.htpasswd` entry and a separate nginx location).

## Troubleshooting

| Symptom | Likely cause / fix |
|---------|--------------------|
| `Run this script as root.` | Run the installer with `sudo bash install.sh`. |
| Installer fails on `/etc/php/8.3/...` | You are not on Ubuntu 24.04 (PHP 8.3). Adjust the PHP version in `install.sh`, the `fastcgi_pass` socket in `nginx/artifacts`, and the `systemctl` service name. |
| `401 Unauthorized` | Wrong username/password, or the credentials were changed by re-running the installer. |
| `413 Request Entity Too Large` | Increase `client_max_body_size` in the nginx site (and in any reverse proxy in front), then `nginx -t && systemctl reload nginx`. |
| `Upload failed (error code 1/2)` | PHP limits too low; adjust `/etc/php/8.3/fpm/conf.d/99-artifact-upload.ini` and restart `php8.3-fpm`. |
| `Could not save file (check permissions)` | Artifacts directory not writable by `www-data`: `sudo chown -R www-data:www-data /var/www/html/artifacts`. |
| `502 Bad Gateway` on `/browser/` | PHP-FPM not running or socket path mismatch: `systemctl status php8.3-fpm` and confirm `/run/php/php8.3-fpm.sock` exists. |
| `405 Not Allowed` on `PROPFIND` / `OPTIONS` | `nginx-extras` (the `dav_ext` module) is not installed: `sudo apt install nginx-extras`. |
| Site not reachable from other machines | Firewall or cloud security group blocking port 80; check `ufw status` and your provider's rules. |
| UI loads without styling or icons | Bootstrap and Bootstrap Icons load from `cdn.jsdelivr.net`; the *browser* needs internet access to it (or vendor the files locally). |
| `nginx: configuration file ... test failed` | Syntax error in `/etc/nginx/sites-available/artifacts`; run `sudo nginx -t` for the line number. |
| Large uploads time out | Raise the nginx and PHP timeouts listed under [Upload limits](#upload-limits), and any proxy timeouts in between. |

## Uninstalling

```bash
sudo systemctl stop nginx php8.3-fpm
sudo systemctl disable nginx php8.3-fpm

sudo rm -f /etc/nginx/sites-enabled/artifacts \
           /etc/nginx/sites-available/artifacts \
           /etc/nginx/.htpasswd \
           /etc/php/8.3/fpm/conf.d/99-artifact-upload.ini

# Remove the UI (keeps artifacts if you move them first!)
sudo rm -rf /var/www/html/browser

# Delete stored artifacts (irreversible)
# sudo rm -rf /var/www/html/artifacts

# Optionally remove packages
sudo apt purge -y nginx nginx-extras php-fpm php-cli apache2-utils
sudo apt autoremove -y
```

## Customization

- **Branding / colors:** edit the CSS variables under `:root` in `html/browser/style.css` (for example `--primary`, `--sidebar-bg`) and the header markup in `index.php`.
- **Sidebar depth / page size:** `buildTree(..., $maxDepth = 5)` in `index.php` controls the folder tree depth; `PAGE = 100` in `script.js` controls how many rows load per "load more".
- **Self-hosted UI assets:** download Bootstrap 5.3.3 and Bootstrap Icons 1.11.3 into `html/browser/` and update the `<link>` / `<script>` tags in `index.php` for fully offline operation.
- **Different storage path:** change `$baseDir` in `index.php` and the matching paths in the nginx config.
